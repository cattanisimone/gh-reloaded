Assumptions

  • Sheet at ≤1023 px, not ≤720 as the issue says — rejected: 720, because a 420 px panel then leaves 28–325 px of list (measured in review 4eee836); the reviewer accepted ≤1023 in the last round.
  • Result intro line uses the image's wording One read-only check per permission type, started only by Test. Nothing was changed on GitHub. — rejected: leaving it out because the strings table does not list it, because the image shows it and the issue text does not contradict it.
  • At ≤1023 px the sheet covers the whole page, sidebar and tab bar included (plan review d2e2175) — rejected: a sheet below the tab bar, because the X button and Esc already close it and a full-page sheet keeps the panel's width for its fields.
  • Dark warning colours #211c14 surface and #9e6a03 border — rejected: reusing the saturated dark yellow, because the reviewer asked for a softer surface "in both themes" and the images are light only.
  • The one-line/stacked threshold stays 560 px unless the worst-content row fails T1 there, then it rises to the smallest passing value ≤ 680 px (plan review 23e7848) — rejected: shrinking or truncating the pill, note or last test, because the reviewer and the images keep that text whole; rejected: a threshold above 680, because it would stack the 1024/1023-closed and 720 rows that the images show on one line.
  • With the couldn't be verified note, the row reads name | pill, (empty) | note, Used for | last test — rejected: putting the note after the last test, because the issue says "under the state" and the reviewer asked for it under the pill; Used for stays on the last-test line as in the images.

Risks and open questions

  • Re-rendering the list must keep an open repository check and focus (an adversarial finding fixed earlier). Default: keep today's node-preserving logic inside the new render(), and keep its regression test.
