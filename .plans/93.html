#93 · Overlay the GitHub Status dot on the header logo as a status badge

Issue #93 · Size: normal (layout change of an injected control) · Goal: the status dot reads as a badge on the GitHub logo, not a stray dot beside it.

What changes for users

  • The dot sits on the bottom-right corner of the GitHub logo, like a presence badge on an avatar, with a 2px ring in the header's own background colour.
  • The header no longer reserves a 24px slot plus a gap for it: the breadcrumb moves left by 32px (signed-in header).
  • States, colours, click / keyboard behaviour, popover and the GitHub Status: … accessible name are unchanged.
  • On the centred narrow-window header (signed out, ≤ 767px) the logo stays exactly centred, since the dot no longer takes a flex slot next to it.

How it works

  • Why anchor positioning, not a wrapper or JS offsets. Wrapping GitHub's logo moves a React-owned node; JS offsets need observers for every layout shift (hamburger appearing, centred mobile row). An absolutely positioned element leaves the flex flow (no slot, no gap) and anchor() follows the logo on every reflow. Supported in Chromium since 125; the live probe confirms CSS.supports("anchor-name: --x").
  • Hit area. The button is a 16px circle (border-radius:50% clips hit testing), covering only the logo's bottom-right corner; the rest of the logo stays the link. The visible mark is the same 10px circle plus a 2px box-shadow ring.
  • Ring colour read from the page, not hardcoded: the signed-in header is #f6f8fa / #151b23, the signed-out marketing header is black in every theme. Fallback when every ancestor is transparent: the existing --ghgs-surface token.
  • States. Hover darkens the mark (brightness(.9)), pressed .85; keyboard focus keeps the 2px #0969da ring, drawn at offset 1px around the circle instead of -2px so it does not cover the dot.
  • Panel. placePanel() keeps reading the dot's rect, so the popover opens under the badge, clamped to the viewport as today.
  • Live probe (anonymous, /cattanisimone/gh-reloaded/pulls): header.HeaderMktg › div[class*=bar] (position:relative) › div[class*=topRow] (flex) › a[aria-label=Homepage][class*=logo] › svg.octicon-mark-github 32×32; at 375px topRow centres the logo between two equal flex slots. Anchors stay the existing ones (href / aria-label / octicon), no class names.

Risks and open questions

  • A 16px target is below WCAG's 24px target size. Growing it would cover more of the logo link. Default: 16px, keyboard access unchanged; tell me if you prefer 24px with a transparent hit area.
  • Browsers without CSS anchor positioning (Chromium < 125). Default: @supports not keeps today's dot beside the logo; no minimum_chrome_version bump.
  • For one scan (~120ms) after GitHub swaps the logo node, the dot can lose its anchor and fall back to its static position. Default: the MutationObserver scan re-marks it; the test checks it settles.
  • Badge offset (centre 4px inside the corner) is a visual call. Default: as mocked; easy to tune.

Out of scope

  • The incident pill, severity line and panel content.
  • Changing states, colours or the 15-minute freshness rule.
