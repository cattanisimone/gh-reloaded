#105 · In-page Triage settings panel for the Notifications modules

cattanisimone/gh-reloaded#105 · Size: normal (new UI surface, new storage key, registry change) · Goal: one place on github.com/notifications to switch each enrichment on or off, pick one triage layout, and go back to GitHub's original inbox in one click, remembered in this browser.

What changes for users

  • A Triage ▾ button sits in the inbox filter row, right after GitHub's own Group by control and with the same look. It opens a compact anchored panel (Esc, outside click or the button close it). It is shown on the inbox whenever the notifications engine runs, even before any module ships, so Show native inbox is always reachable.
  • Show native inbox hides every GH Reloaded enrichment at once without touching the saved switches or layout; turning it off brings them back exactly as they were.
  • Independent switches for Triage, Tags and "Why is this here?", and a choice of one triage layout among three equal 16:9 cards (Integrated navigation is the default).
  • Anything that cannot work yet (a module not shipped in this version, data the token cannot read) is shown disabled with the reason, never as available. Restore defaults resets only these local preferences.
  • Nothing is read from or written to GitHub by the panel; no new permission.

Anchor and insertion

Find the button whose visible text starts with “Group by”, walk up to the nearest ancestor that is a direct child of the flex row (the Group by wrapper), and insert the Triage wrapper as its next sibling, i.e. after Group by and before the alerts node. No GitHub class is used to find it. If “Group by” is missing, nothing is inserted and the next scan retries; no other container is used.

Mechanism: the wrapper has its own class with one @media (min-width: 1012px) rule mirroring Group by's wrapper (ml 8px, width auto, flex-shrink 0, mb 0; below: width 100%, mb 8px). One CSS container query on the panel for the cards, and a position clamp computed on open, resize and scroll.

How it works

The panel never stops or starts modules itself: it only writes preferences. The existing storage listener in content.js feeds the registry, which reconciles which modules run. One source of truth, so the panel, the Options switch from #104 and any other tab stay consistent.

Preferences contract

Rules, each a unit test: a switch writes only its own id (read-merge-write); native inbox writes only its key; a layout click writes only ghntLayout; the registry exposes layout() as the stored value even when Triage is off or native inbox is on (it changes nothing on the page then); running modules = enabled ∧ available ∧ ¬native, exactly as today plus defaults.

Data, permissions, privacy

Token permissions: none. The panel reads no GitHub data; it displays the capability states the engine already has. New storage key ghntLayout (local only), added to PRIVACY.md. No token value is ever read by the panel.

Risks and open questions

  • Anchor text: the Group by control was measured live; the anchor is its visible text, so a renamed label (or another UI language) means no button until the next scan finds it, never a misplaced one.
  • Ordering with #104: #104 ships tags and popover as one module (reasonTags) plus an Options switch. Default: if #104 is merged first, this PR splits the popover into reasonWhy; if not, the Why switch shows “Not available in this version” and the split is listed for #104's rework. The Options switch keeps writing the same merged key.
  • Why without Tags: the popover opens from a tag. Default: switches stay independent (no auto-change); with Tags off, the Why row says “Opens from a reason tag: turn Tags on to use it.” #106 may add another trigger later.
  • Button before any module ships: shown whenever the engine runs on the inbox, as the issue requires (“Show native inbox: always available”, “the panel can ship first”); unshipped modules and the layout are disabled with a reason.

Out of scope

  • Rendering the three triage layouts and the immediate layout switch on the page (#106; verified in that integration).
  • Presets, advanced classification rules, cross-device sync, a dedicated Notifications / Permissions options page.
