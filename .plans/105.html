New approach: a fixed card grid with a text budget

  • Panel 440px (was 380; the mockup panel is about 455), min(440px, 100vw − 32px). Cards become 132px instead of 112px, and the title and description no longer share a row with the radio.
  • 3-column card box model, fixed rows: thumbnail · title (2 lines reserved, 36px) · description (1 line, nowrap) · marker line (18px, “✓ Default” only on Integrated, empty elsewhere). Heights are equal by construction, and nothing needs to measure itself.
  • The radio is visually hidden, not removed. A native <input type="radio"> per card keeps the radiogroup, arrow keys and screen reader semantics (C9). The visible indicator is a 2px accent border, an accent tint and a ✓ badge in the thumbnail corner (C1). The focus ring is drawn on the card with .ghnt-card:has(input:focus-visible).
  • Panel-local text reset: every text element the panel renders sets its own font-size, font-weight, line-height, color and margin: 0 (spacing comes from the grid and flex gaps only), so GitHub’s label (600), p (margin-bottom: 10px) or h2 (24px/36px) rules cannot leak in (C5).
  • Copy limited by a budget: every description must fit on one line in the widest font the tests use with at least 6px to spare. Budget: 95px. Widths at 12px/400: DejaVu Sans In the sidebar 83px, Filter pills 57px, Collapsible list 87px; live GitHub font 77, 55 and 82px. The longest title word, navigation, is 78px at 13px/600, and the whole title Integrated navigation is 160px.
  • One breakpoint rule: a container query on the panel (content box = panel width − 28px of padding, minus a classic scrollbar s if one shows). At ≥ 380px of content, 3 columns; below, rows. Panel = min(440, vw − 32), content = min(412, vw − 60) − s, card = (content − 16) / 3, text column = card − 20. Exact boundary: viewport 439 → rows, 440 → 3 columns with no panel scrollbar (s = 0); 454 → rows, 455 → 3 columns with s = 15; 456 → rows, 457 → 3 columns with s = 17 (Chromium on Windows). The narrowest 3-column card is 121.3px with 101.3px of text: 6.3px above the 95px budget and 19px above the widest live description (82px). From 472 to 1500 a 17px scrollbar leaves 395px (text 106.3px) and a 15px one 397px (text 107px), so both stay 3 columns.
  • Row mode (content < 380px) uses a different template on the same markup, without the reserved rows: thumbnail 96×54 on the left and a vertically centred text column of 18px lines with no gap: title (one line, a second only if it wraps), description, and “✓ Default” only on Integrated (no empty marker line elsewhere). Every row is 54px of content (the thumbnail height, also 3 × 18px), so the rows have equal height without empty bands. The text column is vw − 184: 176px at 360, 16px more than the full title in DejaVu (160px), so from 360 up no title wraps. Below that the rule is row height = max(thumbnail 54px, text), with the text column flex: 1; min-width: 0 and wrapping titles: at 320 (text column 136px) “Integrated navigation” wraps in the wide font, the Integrated row grows to 72px (4 × 18px) and the others stay 54px. Rows may then differ in height; nothing overflows the card and the panel never scrolls sideways.

Test plan

One card matrix test runs every combination of viewport {320, 360, 439, 440, 456, 457, 471, 472, 600, 800, 1011, 1012, 1280, 1500} × theme {light, dark} × font {GitHub’s stack, the bundled GHR Wide Test (DejaVu Sans) as the wide worst case}, with the live global rules in the fixture. Font guard: before the card assertions of the wide run, the test waits for document.fonts.load and requires Collapsible list at 12px/400 to measure ≥ 85px (it is 87px in DejaVu; the live font is 82px), so a missing font fails the test instead of passing it. Scrollbar case: with a short viewport and a forced classic panel scrollbar (overflow-y: scroll plus ::-webkit-scrollbar{width:Npx} injected by the test), run at 15px and 17px at 1500 and 472 (3 columns, text ≥ 106px), and at 17px at 456 (rows) and 457 (3 columns). A scrollbar guard first requires panel.offsetWidth − panel.clientWidth − borders to equal N, so a run without the scrollbar fails instead of passing. A failure message prints the card rect, each child’s rect, the computed font, the measured guard width and the panel and container widths.

The bundled wider font is what gives margin against the live font.

Risks and open questions

  • The 440px panel covers more of the list at 1012–1100px. Default: accept it; the panel is a popover, it closes on Esc or an outside click, and the mockup is wider.
  • The descriptions change from the mockup’s wording (“Horizontal filters”, “Collapsible groups”) to shorter ones. Default: shorter copy; the issue calls them indicative and requires a short description.
  • :has() needs Chrome 105+. Default: fine for an MV3 extension; without it the radio still shows Chrome’s own focus ring.

Out of scope

  • Everything outside the layout cards (button, anchors, preferences, state matrix): unchanged.
  • Rendering the three layouts (#106) and the reasonWhy split (#104).
