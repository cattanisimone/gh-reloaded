#105 · Triage settings panel: re-plan of the layout cards

Size: normal · PR #107 · Issue #105 · Goal: replace the layout-card design, which needed a fix in every review round, with one that meets every constraint by construction.

Revision (review of 3e8836a). (1) One breakpoint rule with an exact boundary: 3 columns when the cards’ container is at least 396px, i.e. viewport ≥ 456px; the matrix adds 439, 440, 455, 456, 471 and 472. (2) The wide font is bundled with @font-face from test/e2e/fixtures/, and a guard checks that it really renders before the card assertions run. (4) Row mode has no reserved lines: the title takes one line, the marker exists only on Integrated, and equal heights are asserted within each layout.
What this re-plan changes and what it keeps. Kept as approved at 6a5f33e and confirmed by the last two reviews: the Triage ▾ button (anchor on Group by, designed fallback after Sort by, Primer look, 1012px switch), the preferences contract (prefs.js, ghntModules, ghntNativeInbox, ghntLayout), the route gating, the state matrix, the thumbnails, permissions (none). The earlier plan still holds for those parts. Replaced: the panel width, the card box model, the card copy, the narrow layout, and the way the card tests measure text.

New approach: a fixed card grid with a text budget

  • Panel 440px (was 380; the mockup panel is about 455), min(440px, 100vw − 32px). Cards become 132px instead of 112px, and the title and description no longer share a row with the radio.
  • 3-column card box model, fixed rows: thumbnail · title (2 lines reserved, 36px) · description (1 line, nowrap) · marker line (18px, “✓ Default” only on Integrated, empty elsewhere). Heights are equal by construction, and nothing needs to measure itself.
  • The radio is visually hidden, not removed. A native <input type="radio"> per card keeps the radiogroup, arrow keys and screen reader semantics (C9). The visible indicator is a 2px accent border, an accent tint and a ✓ badge in the thumbnail corner (C1). The focus ring is drawn on the card with .ghnt-card:has(input:focus-visible).
  • Panel-local text reset: every text element the panel renders sets its own font-size, font-weight, line-height, color and margin: 0 (spacing comes from the grid and flex gaps only), so GitHub’s label (600), p (margin-bottom: 10px) or h2 (24px/36px) rules cannot leak in (C5).
  • Copy limited by a budget: every description must fit on one line in the widest font the tests use with at least 6px to spare. Budget: 95px. Widths at 12px/400: DejaVu Sans In the sidebar 83px, Filter pills 57px, Collapsible list 87px; live GitHub font 77, 55 and 82px. The longest title word, navigation, is 78px at 13px/600, and the whole title Integrated navigation is 160px.
  • One breakpoint rule: a container query on the panel (content box = panel width − 28px of padding, minus a classic scrollbar if one shows). At ≥ 396px of content, 3 columns; below, rows. Without a panel scrollbar, panel = min(440, vw − 32) and content = min(412, vw − 60), so the exact boundary is viewport 455px → rows, 456px → 3 columns. The narrowest 3-column card is 126.7px with 106.7px of text: 11.7px above the budget and 20px above the widest description. A 15px classic scrollbar at full width leaves 397px, so it stays 3 columns.
  • Row mode (viewport ≤ 455) uses a different template on the same markup, without the reserved rows: thumbnail 96×54 on the left and a vertically centred text column of 18px lines with no gap: title (one line, a second only if it wraps), description, and “✓ Default” only on Integrated (no empty marker line elsewhere). Every row is 54px of content (the thumbnail height, also 3 × 18px), so the rows have equal height without empty bands. At 360 the text column is 176px, 16px more than the full title in DejaVu, so no title wraps at any matrix width.

Test plan

One card matrix test runs every combination of viewport {360, 439, 440, 455, 456, 471, 472, 600, 800, 1011, 1012, 1280, 1500} × theme {light, dark} × font {GitHub’s stack, the bundled GHR Wide Test (DejaVu Sans) as the wide worst case}, with the live global rules in the fixture. Font guard: before the card assertions of the wide run, the test waits for document.fonts.load and requires Collapsible list at 12px/400 to measure ≥ 85px (it is 87px in DejaVu; the live font is 82px), so a missing font fails the test instead of passing it. Scrollbar case: at 1500 and 472 with a short viewport and a forced 15px panel scrollbar, the grid stays 3 columns with ≥ 101px of text. A failure message prints the card rect, each child’s rect, the computed font, the measured guard width and the panel and container widths.

The bundled wider font is what gives margin against the live font.

Risks and open questions

  • The 440px panel covers more of the list at 1012–1100px. Default: accept it; the panel is a popover, it closes on Esc or an outside click, and the mockup is wider.
  • The descriptions change from the mockup’s wording (“Horizontal filters”, “Collapsible groups”) to shorter ones. Default: shorter copy; the issue calls them indicative and requires a short description.
  • :has() needs Chrome 105+. Default: fine for an MV3 extension; without it the radio still shows Chrome’s own focus ring.

Out of scope

  • Everything outside the layout cards (button, anchors, preferences, state matrix): unchanged.
  • Rendering the three layouts (#106) and the reasonWhy split (#104).
