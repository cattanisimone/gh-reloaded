#67 · Document classic PAT support for personal Projects

Issue #67 · Size: normal (Settings copy + README, coordinated with open PR #66, website hand-off) · Goal: present fine-grained and classic tokens as two supported options, with the right permissions for each, and no code change.

What changes for users

  • README token setup offers two paths: A. Fine-grained (recommended, least privilege, kept as is) and B. Classic (for Projects owned by a personal account) with scopes repo + read:project.
  • The trade-off is explicit: repo grants read and write on every repository the account can reach; the extension only reads, but the token could do more if leaked.
  • Settings → GitHub tokens shows both permission sets and a second link, Create a classic token ↗, pre-filled with the two scopes.
  • The "fine-grained token, not classic" claim disappears from README and Settings.
  • Website: the exact replacement copy is listed below for the maintainer, because its source is not reachable from here (see Risks).
