cattanisimone/gh-reloaded#11 · Size: normal (new UI surface, new content script, shared-module change) · PR #27 · Revision 2: tile grid, row anatomy, toolbar, collapsible sidebar

Goal: on github.com/issues, a read-only view of the dashboard's full result set as a grid of Project tiles, each listing issues by that Project's real Status, plus a sidebar that collapses to an icon rail.

kept The prototype's data layer (background/my-issues.js, the partial flag in ghGraphQL, query derivation from q and the tab path) stays as is: it already returns updatedAt, nameWithOwner, state and each Project's Status order and color. No GraphQL field is added. changed The layout, the toolbar and a new collapsible sidebar.

What changes for users

  • A one-line toolbar: summary of distinct issues (34 issues in 3 projects), Expand all · Collapse all (grouped view only), and the List | Group by project switch (last choice remembered).
  • Grouped: a responsive grid of collapsible Project tiles (1 to 3 columns), alphabetical, No Project last. Each tile has a Status distribution bar and a text legend; collapsed tiles keep header, bar and legend, so Collapse all is the overview.
  • Inside a tile, issues per Status in the Project's own option order (No Status last), the first 5 per Status then Show N more. Rows: state icon · title · repo#number · time since update.
  • The left sidebar collapses to an icon rail (collapsed by default, in List and grouped view alike), remembered across reloads.
  • Unchanged: an issue in two Projects shows in both tiles with each Project's status; loading, empty, no-token, error and "first N of M" states; List restores the native page; feature off leaves the page (sidebar included) untouched.

How it works

Sidebar: finding it and reflowing without GitHub's class names

  • Grid pane: the track list is rewritten from the live computed grid-template-columns (first track replaced by 48px), set as a CSS custom property on the pane and consumed by our stylesheet, so GitHub's other tracks survive. Flex pane: flex-basis/width on the sidebar, max-width:none on the content sibling.
  • Rail: each nav link keeps GitHub's own icon SVG; its text gets a visually-hidden class (clip, not display:none) and the link a title. Every other sidebar child (the Views section) gets hidden-by-attribute. No transition, so prefers-reduced-motion is respected by construction.
  • The toggle is a <button aria-expanded aria-label="Collapse sidebar | Expand sidebar"> inserted as the sidebar's first child, with a visible :focus-visible outline. State: ghmiSidebar in chrome.storage.local, followed via onChanged; re-applied after Turbo navigations.

Risks and open questions

  • Sidebar reflow and nav anchors are unverified against live github.com from here, and the dashboard markup may differ from the fixture. Default: fixture refreshed from real markup, strict fail-safe (no toggle), and I flag in the PR any step that looks fragile on the real page.
  • Grid track rewrite: if GitHub's pane uses named areas or a responsive track list that changes per breakpoint, replacing the first computed track may misfit. Default: recompute on resize (debounced); if the pane is neither a plain grid nor flex, no toggle.
  • Content max-width: the results column may be capped by its own container, so freed space may not all be used. Default: lift max-width only on the content sibling inside the pane we marked, nothing higher up.
  • Nav text is English-only: GitHub's UI is English, but a localized label would make the sidebar step fail safe (no toggle). Default: accept.
  • 520px tile minimum gives one column below ~1100px of content width. Default: as specified; collapsed sidebar by default helps.

Out of scope

  • Labels in rows (no extra query fields, no room in a tile).
  • Persisting tile collapse or Show N more state; a setting for the per-Status cap.
  • Special handling of any Status name (no "Blocked" or "Done" logic).
  • PR review requests, Project draft items, editing anything, per-owner token fan-out.
