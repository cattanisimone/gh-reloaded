#11 · Group My Issues by Project and status

cattanisimone/gh-reloaded#11 · Size: normal (new UI surface, new content script, shared-module change) · PR #27

Goal: on github.com/issues, a read-only Project → Status → issues view of the dashboard's full current result set, next to the native list.

prototype PR #27 already has a working prototype (rebased on main 0.8.0, the three earlier review threads resolved). This plan keeps its architecture and lists what implementation still adds: tests for every acceptance criterion and a few behaviour gaps.

What changes for users

  • A List / Group by project switch on the My Issues dashboard. The last choice is remembered.
  • Grouped: one collapsible group per Project (alphabetical), inside it the Project's own Status options in board order, then No Status; a final No Project group. Counts on every group.
  • An issue in two Projects shows in both, each time with that Project's status.
  • Groups follow the search box, filters, saved views and the Assigned / Created / Mentioned tab, and cover the whole paginated result set.
  • Clear loading, empty, no-token, error and "showing first N of M" states. Switching back to List restores the native page untouched.

Data, permissions, privacy

  • Reads: issues matching the dashboard query, their Project memberships, Status values and the Projects' Status options, under the user's default token (the dashboard is that account's own view).
  • Stores: two new chrome.storage.local keys, ghmiEnabled (feature switch) and ghmiView (list | grouped). PRIVACY.md updated.
  • Sends: nothing new; only GitHub's API, as today. No new permission: api.github.com is already a host permission.

Fixture: refresh test/e2e/fixtures/my-issues.html from the live dashboard (search box, tabs, results list), so the mount anchor is tested on real markup, not hand-written HTML. Every new e2e spec runs 3× (--repeat-each=3).

Risks and open questions

  • Dashboard DOM churn: the mount and the "hide native list" step rely on finding the results block. Default: anchor on content (the issue-link rows and the search box), fail safe (no switch rather than a broken page), refresh the fixture from real markup.
  • Saved views whose query is not in the URL: if a saved view only shows up in the page and not in ?q=, we read the search box's visible value instead. Default: URL q → search box value → tab path.
  • Token choice: issues span many owners, but one search uses one token. Default: the default token; Projects of owners it cannot read degrade to No Project. Per-owner tokens could come later.
  • Cap of 500 issues (10 pages × 50). Default: keep it, with the explicit "first N of M" notice.
  • Project order: GitHub exposes no personal Project order. Default: alphabetical, No Project last; issues most recently updated first.

Out of scope

  • PR review requests, Project draft items, assignment through custom Project fields (excluded by the issue).
  • Editing anything (status, assignee, Project): the view is read-only.
  • Per-owner token fan-out for one dashboard search.
