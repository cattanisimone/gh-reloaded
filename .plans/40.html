#40 · Manifest description over the Chrome Web Store limit

cattanisimone/gh-reloaded#40 · Size: normal (new CI check) · Goal: fix the 0.10.0 package and catch store-limit violations in npm test, before a release.

What changes for users

  • The next release (0.10.1) reaches the Chrome Web Store, so users on 0.9.0 finally get Standup mode.
  • The store listing's short description is reworded to fit the limit, and still names the same features.
  • Contributors: a PR that breaks a store constraint now fails CI instead of failing the release job.

The description

Now · 139 chars (limit 132)
Small UI enhancements for GitHub: dependency graphs, quick-create, board dependency arrows, full-width boards, standup mode, HTML previews.
Proposed · 129 chars
GitHub UI enhancements: dependency graphs, quick-create, board dependency arrows, full-width boards, standup mode, HTML previews.

Only "Small UI enhancements for GitHub" → "GitHub UI enhancements" changes. Every feature named today stays. My Issues by project is not in the description today and does not fit with 3 chars to spare, so it stays out.

How it works

Files referenced by the manifest: background.service_worker, icons, action.default_icon, options_ui.page, each content_scripts[].js/css, sandbox.pages, web_accessible_resources[].resources. The test reads the path list from the release workflow's zip -r step and does not keep a second copy, so a new top-level folder that is referenced but not zipped fails the test (the package would be broken even though the file exists locally).

Version rule per Chrome docs: 1 to 4 dot-separated integers, each 0–65535, no leading zeros, not all zeros. Description: 132 chars, name: 75 chars. Length is counted in characters (code points), the way the store counts it.

Risks and open questions

  • Parsing the zip list out of release.yml depends on the step's shape. (default: match the zip -r "…zip" \ … command with a regex and fail loudly if it is not found, rather than add a YAML dependency.)
  • The store may enforce other rules that are not in this list (for example the 128px icon). (default: limited to the four rules the issue lists; others go to Follow-ups.)
  • The release job could also run the same check before uploading. (default: no; it is in CI already, and the release steps stay as they are.)

Out of scope

  • Re-publishing v0.10.0: the fix ships as 0.10.1 through the usual release PR.
  • Files referenced from inside HTML pages (e.g. options.html → options.js); those live in already-zipped folders.
  • Changes to release.yml.
