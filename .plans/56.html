#56 · Board dependency arrows: the toggle never mounts

Size: simple (one selector, plus fixture and tests; plan and implementation in one pull request) · Goal: mount the arrows switch on GitHub's current Board markup again, without depending on a CSS-module prefix.

What changes for users

  • The "Dependency arrows" switch appears again in the view tabs bar on every Board view.
  • It comes back after GitHub re-renders the bar, as it was designed to.
  • No change to its placement or look (that is #57).

How it works

The same selector Standup mode already uses: the stable local name plus __ (current naming), with the old prefixed form kept as fallback for an older build. The switch is still appended to that container, the same element as before, so placement does not move. The suite stayed green because board.html carried both class names on one element, and nested the container inside the nav (the live page has it the other way round): the fixture is fixed to mirror the live page.

Risks and open questions

  • GitHub drops the __ suffix form too (default: out of scope; a role-based anchor on nav[aria-label="Select view"] would need a new mount point, which is #57's placement work).
  • Changing the shared board.html breaks another feature's test (default: run the whole suite; adapt only fixture-structure assumptions, never weaken a test).

Out of scope

  • Moving or restyling the switch (#57).
