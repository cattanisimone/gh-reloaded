#96 · GitHub Status: red line, green dot and pill touching search during a critical incident

cattanisimone/gh-reloaded#96 · Size: normal (three defects, layout change, CSS + logic + tests) · Type: fix → patch

Goal: during an incident, the header shows one consistent signal inside the header bar: a dot in the incident's colour and a pill that keeps a gap from the search field, with no extra line.

What changes for users

  • No more red line across the page between the top bar and the repository tabs. The pill alone signals the incident inside the header bar, as #88's default placement (B) intended.
  • The dot matches the pill. While githubstatus.com lists an open critical incident, the dot is red and its accessible name says "Critical incident", even when the feed's overall indicator still says "none".
  • The pill keeps a gap from the search field: the same 8px gap the header uses between its other controls, at every width. On narrow windows the pill gets shorter, as it does today.

Root causes

SymptomCause (verified)Fix
Green dot, "critical incident" pillrelevance.js dotState() reads only status.indicator. On 2026-10-21 the live summary.json had indicator: "none" ("All Systems Operational") and an open incident "Delays for Pull Requests and Webhook deliveries" with impact: "critical". The pill reads the incident's impact, so the two disagree.The dot takes the worst of: the page indicator, the impact of each open incident, and the status of each affected component (degraded / partial → minor, major outage → major). Maintenance only wins when nothing is worse.
2px red rule between the header rowspaintLine() appends div.ghgs-line to the header, absolutely positioned at the bottom of the logo row, and sets position: relative on the header. In the two-row GlobalNav header it reads as a detached full-width rule.Remove the line: no #ghgs-line, and the header's position is never touched. The pill already carries the severity colour and icon.
Pill touches the search fieldfindSearch() climbs from the search control only while the parent has one child. In the live header the search sits in a group with another element (a joined button or a hidden one, like the d-none sibling the anonymous header shows), so the climb stops early. The pill lands inside the group, whose row has no gap: pill x 464 + 250 = 714 = search start.Climb to the outermost search wrapper: skip siblings with no layout box when counting children, and keep climbing while the parent row has no column gap. The pill then sits in the row whose gap spaces the controls. A measured safety net, tested so it cannot hide the anchor: if the measured space between the pill and the search is still under the header's gap (8px), the pill gets margin-inline-end for the difference only.

Risks and open questions

  • Signed-in markup is inferred from the issue's measurements, not captured. Default: the climb uses only layout facts (rendered siblings, computed gap), not class names, so it works whatever the group is called; the measured margin is the safety net.
  • Dot shows components too. A degraded component with no incident turns the dot amber. Default: yes, it is a real reported problem and the panel already lists it.
  • Line removed rather than moved. The issue asks for "no extra row or rule". Default: remove it; the pill carries colour and icon. Say if you would rather keep a tint inside the bar.
  • Dot not overlaid in the report (x 100 beside the logo): likely an installed version older than #93. Default: not changed here; the maintainer confirms the version during the live check.

Out of scope

  • Relevance rules (which incident gets the pill), the panel, the fetch and its cache.
  • Fallback placement A (bar above the header).
