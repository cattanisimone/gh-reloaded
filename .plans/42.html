#42 · Improve minimum column width in My Issues

Size: normal (changes a layout) · Goal: a project tile only gets a neighbour when every tile still leaves an issue title enough room to read.

What changes for users

  • The Project tile grid stays responsive (1, 2, 3… columns), but a new column is only added once every tile keeps at least ~320px for the issue title (about 43 characters), instead of ~220px today.
  • On a 1920px monitor the grid shows two wide tiles instead of three cramped ones; three columns start around 2000–2200px depending on the sidebar.
  • On a 2560px monitor it shows three columns instead of four.
  • Narrow and mobile widths are unchanged: one full-width column, status gutter stacked above its rows.
  • No color, theme, data or settings change.

How it works

CSS only. Today the grid track minimum is a bare 520px. After, it is derived from what a row needs: the title's readable minimum plus the fixed furniture around it, so the breakpoints follow from the content instead of being tuned to a monitor.

Columns = ⌊(grid width + gap) ÷ (tile-min + gap)⌋, which is exactly what auto-fill already does; no JavaScript, no resize observer, no re-render. min(…, 100%) keeps the single-column case shrinking to any width, so mobile is untouched, and the existing 460px container query (stacked gutter, type dot) keeps working for one-column narrow tiles.

Risks and open questions

  • Laptops with the sidebar open drop from 2 to 1 column (1440/1512 expanded, 1280 collapsed). The title goes from ~250–290px to ~830–900px; collapsing the sidebar brings two columns back at 1440+. (default: accept, it is the issue's “readability over column count” rule)
  • The 320px title minimum (~43 characters at 14px) is a judgement call. Below ~300px the 1920px monitor in the issue still gets three columns. (default: 320px, one custom property to tune)
  • The furniture term uses the typical widths of the ref and type chips, not their worst case (a long repo-prefixed ref or type name can take ~40px more, still leaving ≥ 280px). (default: typical, so a single long chip does not cost a column)
  • Real github.com's content area may be narrower than the fixture's at large widths, giving fewer columns than the table. (default: fine, the rule is the same; checked manually)

Out of scope

  • A user setting for the column count or minimum width.
  • Changing the row anatomy (chips, gutter width, title wrapping).
  • Other features' layouts (board, standup mode).
