#122 · Image gallery for repository folders

Issue: cattanisimone/gh-reloaded#122 · Size: normal (new feature, new UI, new settings) · Goal: browse the images of the current folder in a lightbox from an image file page, and come back to exactly where you started.

What changes for users

  • On a repository image page (PNG, JPEG, WebP, GIF, SVG in Preview) the gallery opens on that file, showing 3 of 8, with previous/next, Esc, close and Open file on GitHub.
  • A neutral small Gallery button (image icon + text, like the issue's mockup) in the file header opens the same set at any time; it stays when automatic opening is off.
  • Browsing never touches the URL or history; closing restores focus and scroll. GitHub's one-key shortcuts are blocked only while it is open.
  • When the folder list cannot be read the native preview is untouched, Gallery is inactive and an accurate notice says why (never "empty folder").
  • Settings: an Image gallery feature row (on) with Configure →, and an Open automatically switch (on) under Advanced.

Timing and suppression

  • Set not yet known: Gallery is shown aria-disabled with "Loading the folder list…" as its description; a click does nothing. Auto-open fires on arrival only if the URL is unchanged and no pointerdown, keydown, wheel or scroll happened since the visit began; a late set for a previous URL is dropped (visit token).
  • Keys: a capture-phase keydown/keypress listener on window, active only while open, handles ←, →, Esc and Tab trapping and stops propagation of everything else, so y, t, /… never reach GitHub.
  • Open file on GitHub: a real <a href> (encoded path segments, raw ref). Plain click: if it is the current file, just close; otherwise send SUPPRESS {url} to the background (kept in a Map keyed by sender.tab.id, in memory only, 10 s TTL), then location.assign. The next content-script visit in that tab asks CONSUME: it matches only that URL, is removed on first read, and any visit to another URL discards it. Modifier / middle click: browser default new tab; the new tab follows the setting (its tab id is unknown in advance) and the PR records that limit.
  • Images: shown by the same same-origin URL GitHub's own page uses (probed: /blob/main/icons/icon48.png?raw=true → 302 → raw host, allowed by GitHub's CSP for its own image). Only adjacent images are preloaded; closing clears src of pending loads. On an error, the background PROBE reads the file through the Contents API / Git blob: 404 with a readable source → "removed"; bytes received → shown as a data: image, or "damaged" if that also fails to decode; otherwise neutral.

Data, permissions, privacy

  • Token permissions: none new. The listing uses the Contents API, already covered by the documented Contents: Read-only / repo; public repositories need no token. No write call.
  • Storage: two new boolean keys, ghigEnabled and ghigAutoOpen. Nothing else: no image data, no "last image", no notice-shown flag, no suppression flag (memory only).
  • Network: api.github.com via the existing client; images from github.com's own image URL in the user's browser, as GitHub shows them, no token attached. No third party, no telemetry.
  • SVG: only ever an <img> source, never inserted as markup.

Risks and open questions

  • Order of numeric / mixed-case names (B.png a.png 10.png 2.png) vs GitHub's directory page. (default: keep the source order, which matched the embedded tree on this repo; verify live on a public folder and record any limit.)
  • Private image by URL from a content-script <img> under GitHub's CSP. (default: same URL as GitHub's own image; on error the token path via PROBE; else neutral message.)
  • Service worker restart drops the suppression entry. (default: the gallery then reopens per setting, the safe direction; recorded in the PR.)
  • Assumptions (also on the issue): pending Gallery is inactive, not queued; Gallery and the notice move to an own line inside the header box when GitHub shows its kebab (≤ 767 px) or Gallery does not fit inline; a notice that does not fit inline moves to the own line before it is truncated; new-tab Open file follows the setting; Gallery is the group's first child (before Copilot when present), a neutral small button as the issue requires.
  • Copilot / Add to space markup not observable with the factory account. (default: anchor by structure, never by their labels; fixtures from the review's measurements; listed under "Not verified on live github.com".)

Out of scope

  • Thumbnails, grid, subfolders, PR diffs, issue / comment attachments, annotations, bulk download, persistent caching, localization, an in-lightbox auto-open toggle, retry or Settings actions in notices, changes to HTML preview.
