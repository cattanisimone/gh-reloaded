#85 · Show personal PR triage in a two-group summary panel

Size: normal (new UI surface, rewrite of the bar) · Goal: on a repository's /pulls page, replace the count-only “On this page” bar with a compact My PR triage panel listing Needs my action and Waiting on others, above an untouched native list.

What changes for users

  • Above the search box, a panel My PR triage · On this page with two groups side by side: Needs my action and Waiting on others, each with a count.
  • Each entry is a link to the PR: title, #number and the reason (“Review requested”, “Changes requested by sam”, “Waiting on author”…). At most 5 per group, then Show N more.
  • Collapse (chevron button, aria-expanded) hides the groups but keeps the header and counts. Hide triage still turns everything off, persisted as today.
  • Loading, missing token, refusal, rate limit and unreadable PRs are each said in words, never shown as an empty group. The row labels stay as secondary context.
  • Same classifier, same single batched query: no new API calls, no new rules, no new stored setting.

How it works

  • Live structure (anonymous probe): the title row (Pull requests + buttons) and div[role="search"][aria-label="Pull requests"] sit in the PageLayout header; the bordered list (listContainer__<hash> › toolbar › ul[role=list]) and pagination follow in the content area. Today's bar is inserted inside the bordered list; the panel moves above the search, so search, filters, list and pagination are all below it, as the issue asks.
  • The anchor is a role + ARIA attribute, no class names. Primary anchor asserted on current markup in a test; the fixture keeps real Name__hash classes plus the old-prefix variant.
  • Render: groupEntries(me, rows, facts) returns {yours:[], waiting:[], team, unavailable, loading} in native row order, one group per PR (classifier's single placement). The panel is rebuilt by key (number + title + reason), so a filter, page, SPA or repository change reconciles in place: no duplicates, no stale titles.
  • Temporary UI state (collapsed, expanded groups) lives in a module variable, keyed per repository; never written to storage.
  • Today's jump buttons are dropped: the entries are real links to /pull/<n>.

Risks and open questions

  • Placement: above the search (issue: “search, filters … below the panel”) rather than inside the bordered list as today. Default: above the search landmark; nothing if it is missing.
  • Team requests and unavailable PRs belong to neither group (unchanged rule). Default: counted in the header as “1 team request · 1 unavailable”, not listed.
  • Collapsed state lasts for the tab (module memory), reset on reload; not stored, as the issue requires.
  • PNG: main only has screenshots/pr-triage.svg. Default: redraw the SVG and add screenshots/pr-triage.png rendered from it with headless Chromium.
  • Jump buttons are removed (entries are links). Default: remove; the row labels remain for in-list scanning.

Out of scope

  • Global inbox, the global github.com/pulls page, notifications, unread or merge-ready states.
  • New classification rules, repository-wide fetching, new API calls or storage keys.
  • Replacing or reordering GitHub's own list; version bumps, releases, store publication.
