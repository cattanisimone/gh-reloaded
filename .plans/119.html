#119 · Quick assignment in the Projects issue side panel

cattanisimone/gh-reloaded#119 · Size: normal · PR type fix: · Goal: the same Assign me / Unassign me / ✕ controls when an issue is opened in a Projects v2 side panel, bound to exactly that issue.

What changes for users

  • With Quick assignment (Experimental) on, an issue opened from a Projects table or board shows Assign me / Unassign me and a ✕ per assignee in the side panel, exactly as on the full issue page.
  • Same safety: GitHub's own picker does the change, Assign me never removes anyone, ✓ only after a read-back of that issue.
  • Closing the panel, switching item, opening a sub-issue inside the panel or going back/forward drops the controls and any pending status of the previous issue.
  • No controls on draft items, pull requests, read-only panels, or when the panel's issue cannot be identified with certainty. Off by default, unchanged.

How it works

Identity needs two agreeing sources: the URL's issue=owner|repo|number and the panel's own title link (h1 a[href="/owner/repo/issues/number"], observed live). While GitHub swaps panel content the two disagree for a moment: no controls, retry on the next scan. The key carries the surface (panel: / page:), so every existing key !== page.key guard (picker drive, read-back loop, final status) also stops on close, item switch, sub-issue or back/forward. The picker stays global (one Primer SelectPanel at a time, portaled inside the panel, observed live); the section, list and edit button are looked up only inside the panel root.

Risks and open questions

  • Our synthetic Escape (to save via the picker) could bubble to the panel and close it. Real Escape does not (live). Default: keep the current dispatch, add a fixture test, check live during implementation by assigning/unassigning the factory account on a playground issue; if it closes the panel, dispatch on the picker element only.
  • Panel title link moves or changes shape. Default: no controls (anchor missing → retry), never URL-only identity.
  • Two panels or stale panel content after fast switching. Default: exactly one matching panel or nothing.
  • Org-owned Projects not verifiable live. Default: same matcher, fixture covers orgs/; PR body lists it under "Not verified on live github.com".
  • Assumption: screenshots/quick-assign/quick-assign.svg stays as is, since the panel controls are visually identical; README text is updated.

Out of scope

  • Pull request side panels, other Projects surfaces (roadmap cards, item hovercards), changing assignment semantics or the native picker, enabling the experiment by default.
