#57 · Board: Standup and the arrows switch in the filter row, as native buttons

Size: normal · Goal: move both board controls out of the view-tabs bar (where they cover tabs) into the filter row, left of GitHub's View button, styled exactly like Primer buttons.

What changes for users

  • Standup and the dependency-arrows control sit in the filter row, in this order, just left of View. They no longer cover or truncate view tabs at any width.
  • Standup becomes a default Primer button (icon + "Standup", 32px). The pill switch becomes a 32×32 icon button with aria-pressed and the tooltip "Dependency arrows (experimental)"; when on it shows the selected fill and a blue icon.
  • Hover, pressed and keyboard focus look like GitHub's own buttons, and colours follow the GitHub theme you picked (light/dark), not only the OS setting.
  • Still Board-only, as today. While presenting in Standup mode the filter row is hidden, so the arrows control is hidden too (arrows keep their state).

How it works

Live structure (probed 2026-10-14, all widths): div[role=region][aria-label="View filters"] is display:flex; gap:8px; justify-content:space-between, children Box__… (filter, flexible) · [Box__… Discard · Divider__… when dirty] · viewButtonContainer__… (the 32px "View" Primer button). Both content scripts get a small identical findFilterRow() (about 15 lines each) so each feature still ships on its own. Re-renders: GitHub's React tree can drop our nodes; the existing 800ms scan re-mounts by id (no duplicates) and re-applies aria-pressed/title from storage.

Styling uses GitHub's own Primer variables with the measured light values as fallback: --button-default-bgColor-rest/hover/active/selected, --button-default-borderColor-rest, --button-default-shadow-resting, --button-default-fgColor-rest, --fgColor-muted, --fgColor-accent, --focus-outlineColor. font-family: inherit, 14px / 500 / 21px, padding 0 12px (icon button: 32×32, no padding, 16px icon), transition copied from the View button.

After implementing I will load the extension against the same structure and repeat the probe; the private-board case (other owners' markup) stays "not verified" in the PR.

Risks and open questions

  • The region's aria-label "View filters" is English text; GitHub's UI is English-only today. (Default: accept, require the "View" button too, and log nothing when absent.)
  • Below ~700px GitHub may collapse the filter row differently. (Default: out of scope; the controls simply do not mount if the anchors are gone.)
  • The arrows control is hidden while presenting in Standup mode. (Default: accept; adding it to the standup bar is a follow-up.)
  • Tooltip is the native title, not Primer's JS tooltip. (Default: title + aria-label; no injected tooltip component.)
  • Two copies of the small anchor helper. (Default: duplicate rather than add a shared content-script file to the manifest, so each feature stays independent.)

Out of scope

  • Changing what Standup mode or the arrows do, the Settings page, or other board features.
  • An arrows control inside the standup presentation bar.
