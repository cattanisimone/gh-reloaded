#134 · Go to failed step / Failed steps: N on Actions job pages

cattanisimone/gh-reloaded#134 · Size: normal (new UI surface, placement logic inside GitHub's sticky header) · Goal: from any scroll position on a failed job, reach a failed step's title in one gesture (one failure) or two (several).

What changes for users

  • Job page with one failed step: a Go to failed step button; one click scrolls its title just below GitHub's sticky bars (88 px) and focuses it.
  • Two or more failed steps: Failed steps: N opens a list of their names in execution order; choosing one goes there and closes the list.
  • The button sits in GitHub's sticky job header when it fits there without changing GitHub's text or height; otherwise it is fixed at the window's bottom-right edge. It is always in the window, no scrolling needed.
  • Same «Actions log shortcuts» switch as #132; no request, no token, nothing stored. Two Options sentences change.

How it works

No background message, no network: the feature never touches chrome.runtime.sendMessage. Own mutations are discarded (observer.takeRecords() after placing) so placement cannot loop.

Landing a step

  • Covered height read from the page: the summary's own computed sticky top (GitHub sets top: 88px), fallback header bottom + 8.
  • window.scrollBy(0, title.top − covered), then re-check in the next two animation frames (logs render progressively) and correct; targets the element, never a stored offset. URL, history and details[open] unchanged.
  • Focus: summary.focus({preventScroll:true}) (it is natively focusable, tabIndex 0 live, and focusing does not toggle). If focus does not land, a polite role=status says «Moved to failed step: <name>».

Risks and open questions

  • Fit test measures GitHub's text by geometry; a font load or late render can change it after placement (default: refit on header ResizeObserver and title-block mutations, and once on document.fonts.ready).
  • Continue-on-error and in-progress markup not yet captured live (M1/IP1) (default: count exactly data-conclusion="failure"; record the observed markup in the PR; if a running job never sets it, the control appears only when the page shows the failure).
  • (d) under mobile browser chrome or at 200 % zoom (default: position:fixed with env(safe-area-inset-bottom); if H2(3) shows it under the visual viewport, offset by visualViewport).
  • A pathologically long log between steps (>1 M px): scroll converges over a few frames (default: up to 3 correction frames, then stop).

Assumptions

  • Signed-out job pages (no search block): (a) is the header's last flex item and (b) right-aligns to the header's padding edge — rejected: no control when signed out, because the step list is still shown and the jump still helps.
  • No new file in manifest.json: logic goes in the existing model.js/content.js — rejected: a separate failed-steps.js, because criterion 14 rules out any manifest entry.
  • List uses the ARIA menu pattern (aria-haspopup="menu", aria-expanded, roving focus, Home/End too) and closes on Tab or outside click — rejected: listbox, because entries are actions, not a selection.
  • "Release notes" = the changelog entry Release Please builds from the PR title; no hand-written docs/releases file — rejected: a notes file, because 1.x releases have none.

Out of scope

  • Run page; expanding/collapsing steps; URL or history changes; any request, token, permission, manifest entry or storage.
  • Any wording naming a step as the cause; a separate switch; moving or restyling #132's row.
  • Download logs, Find first error, log search or analysis.
