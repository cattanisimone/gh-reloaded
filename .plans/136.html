#136 · Expand all resolved / Collapse all resolved on the PR Conversation tab

Issue cattanisimone/gh-reloaded#136 · Size: normal (new UI surface, new feature folder and toggle) · Goal: one bar above the first loaded resolved conversation that opens or closes all loaded resolved conversations at once, with a true count.

What changes for users

  • On a pull request's Conversation tab, a compact bar sits directly above the first loaded resolved conversation: the count on the left, Expand all resolved / Collapse all resolved on the right.
  • Expand opens the loaded resolved conversations one after another while GitHub loads each one. The bar says "Expanding…" and the final count is honest ("K of N … expanded" when some did not open).
  • When the page has GitHub's "Load more…" blocks, the copy says "loaded" and "more may be hidden". The bar never clicks "Load more" and sends no request of its own.
  • Unresolved conversations, review summaries and everything else stay as they are. With no resolved conversation, the page is unchanged.
  • A new Resolved conversations switch under Settings → Features, on by default. It has no other options.

How it works

Expand sequence (measured live, anonymous, cli/cli#10513, 66 resolved)

Anchors found on the live page (anonymous and signed in alike)

  • Thread: the custom element review-thread-collapsible (a tag name, not a CSS-module class). Its header row holds button.review-thread-chevron[aria-expanded] (no text, named by a tooltip) and span.Label with the text Resolved. We match the visible "Resolved" label text, not data-resolved, which only serves as a cross-check in tests. Open state: aria-expanded="true" plus class open. The body is [data-target="review-thread-collapsible.body"] and gets a direct-child include-fragment until the content arrives.
  • "Load more": form.ajax-pagination-form with a button whose visible text is "Load more…", both per review (more_threads) and per timeline (timeline_more_items). We detect it by the visible text "Load more", scoped to the discussion.
  • A minimize form's <option>Resolved</option> also contains "Resolved". We exclude it by scoping the text match to the thread's own header row.

Data, permissions, privacy

Token permissions: none. No API call, no message to the background, no fetch, no new host permission. The only network traffic is GitHub's own lazy load of each opened thread, the same request a click by hand triggers. Stored: one boolean, ghrcEnabled, in chrome.storage.local like every other feature switch. It is listed in PRIVACY.md. The expanded state is never stored.

Risks and open questions

  • A thread whose content failed to load keeps aria-expanded="true". We count it as not open, and Expand never clicks it (a click would close it), so it stays as GitHub shows it and only "K of N" reflects it. Assumption: honest count over retrying.
  • A thread opened by hand counts as open only once its content has loaded, so the bar can show Expand for about a second before it switches to Collapse. Default: accept the short delay. It keeps one definition of "open" everywhere.
  • The concurrency and the bound are measured, not guessed: one at a time and 6 s per thread. Default: keep them as constants in model.js and re-measure live during implementation.
  • GitHub renames review-thread-collapsible or the "Resolved" label. Default: no bar, no error (AC 7). There is no fallback container.
  • Turbo re-renders the turbo-frame that holds the bar. Default: the observer re-runs scan(), which reinserts the bar exactly once. A test covers it.

Out of scope

  • Files changed and its Comments panel, restoring Option/Alt-click, activating "Load more", resolving or unresolving threads, remembering the expanded state, and any setting beyond the on/off switch.
