Issue cattanisimone/gh-reloaded#98 · Size: normal (visible layout change, fixture rework) · Goal: the band reads as the card's own footer, closed by the card outline and set apart by a 1px divider, in light and dark.

Root cause, measured on a live public board

Probed anonymously: github.com/orgs/github/projects/4247 (Board view), light and dark, at 1x and 2x, with the extension's real content.css and a copy of fitRow() injected.

  • fitRow() measures the outer card (border 0), so it widens the band by 1px on each side and 13px down: the band paints over the inner box's left, right and bottom border. In light mode the band is the same #f6f8fa as the column, so the card has no edge there: it looks open at the bottom. Confirms hypothesis 1, plus a second cause the issue did not name.
  • Same cause: the band's text starts at x=37 while the card's title is at x=38 (1px off the card's text column).
  • The test fixture puts the border on the card itself and uses a white column, so the suite (leftGap 0, "no divider") passed while live was broken.
  • Soft text: on the live board the offsets are whole pixels (1px, 13px) at 1x and 2x. A fractional x offset (0.25, 0.37, 0.5px) changed the anti-aliasing of 12px text by under 5% in Chromium on Linux. Hypothesis 2 is not confirmed here, and macOS text rendering could not be checked. See Risks.

What changes for users

  • The card outline is closed around the band again: left, right and bottom border stay visible, in light and dark.
  • A 1px divider (--borderColor-muted) separates the band from the card content, as #91 specified. The muted band stays.
  • The band's text lines up with the card's title and fields (12px inset inside the border, not 11px).
  • Offsets snap to whole device pixels, so the band never lands half a pixel off at any zoom or card width.

How it works

No class name is used to find the frame: it is found by its computed border, so it survives the next Name__hash rename and also covers the older markup where the card itself has the border.

Risks and open questions

  • Soft text not reproduced. Offsets are whole pixels on the live board, and fractional offsets don't change anti-aliasing in Chromium on Linux. Snapping removes the fractional case anyway. (Default: ship the snap and list "text sharpness on macOS high-DPI" under Not verified on live github.com for the maintainer to compare the footer text with the card text.)
  • The private organization board in the report may use a different card markup. The frame lookup is by computed border, not class, so a board where the card itself has the border behaves as today, minus the overlap. (Default: no class-based anchor.)
  • The band stays the same grey as the column, so in light mode only the card border and the divider set it apart. The issue keeps the band, so I keep it too. (Default: keep --bgColor-muted.)
  • When no ancestor has a border, the code measures the card. That is the same geometry as today, not a different container. (Default: keep it as the designed fallback, with the primary path asserted in a test.)

Out of scope

  • Changing the band colour, font size or the dialog.
  • Other features' card injections (Standup badges): not affected by fitRow.
