#58 · Board dependency arrows: hide done-to-done, keep off card text, make readable

cattanisimone/gh-reloaded#58 · Size: normal · Goal: arrows on a Projects Board carry only useful links, never cross a card's text, and stand out from the cards' borders. · PR title: feat: route board dependency arrows around cards, hide done-to-done links and highlight on hover

What changes for users

  • An arrow whose both ends are closed (issue closed, PR merged or closed) is no longer drawn. One closed end still draws.
  • Arrows run in the gaps: a same-column pair gets a short bracket in the column's side padding, a cross-column pair leaves from the side, runs in the 8px gap between columns and enters the target from the side. Where a route must cross another column, the line is cut out under each card, so it reads as passing behind it.
  • Higher contrast: solid GitHub muted grey / danger red (from GitHub's own CSS variables, so light, dark and high-contrast themes follow), 2px stroke with a thin halo in the page colour, a 10px head.
  • Hover or keyboard focus on a card highlights its own arrows and fades the others; leaving restores them.
  • An arrow to a card scrolled out of its column (or not rendered) is not drawn.

Mockup

Dark mode uses the same shapes with GitHub's dark muted grey and danger red; the halo takes the column background colour.

How it works

StepRule
Done-nessCard's own state icon (svg[aria-label] starting with Closed / Merged, e.g. octicon-issue-closed, octicon-git-merge) when the card shows one, else the issue state the dependency API returns for that issue (each end of a visible edge appears in the other end's lookup). Never a column name. visibleEdges drops an edge only when both ends are done.
PortsSide midpoints only (never top/bottom), on the card box .board-view-column-card. Several arrows on one side spread along it (top + h·(i+1)/(n+1)), clamped 10px from the corners.
Same columnRight side → out into the column's side padding (~9px live) → vertical → back into the target's right side. Overlapping brackets get stacked lanes 3px apart.
Adjacent columnsFacing sides → vertical run at the centre of the inter-column gap (8px live) → into the target. No card crossed.
Columns further apartHorizontal at the source's port y into the gap next to the target column, vertical there, then into the target. The cards of the columns in between are cut out of the line by an SVG mask, so it passes behind them.
VisibilitySkip an end whose rect has no size or lies outside its column's scroll viewport (the column-drop-zone scroller, found as the card's nearest scrolling ancestor, not by class). The overlay is clipped to the board's visible rect.
Colourvar(--fgColor-muted, #59636e) and var(--fgColor-danger, #d1242f), falling back to the current dark values under prefers-color-scheme; a 4px halo in var(--bgColor-muted) under each path; head 10px in user space (constant on any zoom); opacity 1.

Risks and open questions

  • Swimlanes (Group by): the vertical run in a gap may cross a swimlane header. Default: swimlane header rows are cut out by the same mask as cards (found as the row that holds the group's name, not by class).
  • The overlay sits at z-index: 2147483646, above GitHub's own menus and the issue side panel. Default: clip to the board's visible rect and lower the z-index under Primer's overlay layer, so menus and the side panel cover the arrows.
  • Narrow gutters (9px padding, 8px gap) fit about three stacked lanes. Default: beyond that, lanes share the outermost position rather than enter the cards.
  • "Done" includes closed as not planned. Default: yes, it is GitHub's closed state, as the issue asks.

Out of scope

  • Arrows to cards the board has virtualised away (narrow viewports), as the issue notes.
  • The on/off switch (done in #56/#60) and Table/Roadmap views.
