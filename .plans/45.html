#45 · Board: full width and Standup mode do not work

Size: normal · Goal: make Full-width board and Standup mode work again on the Projects markup GitHub serves today, and keep them working on the markup it served before.

Root cause (checked on a live public board, 2026-10-13)

GitHub's Projects app has dropped the file prefix from its CSS-module class names. Both features find the board only through those prefixes, so on the current markup every selector matches nothing. Board detection (the selected view tab's octicon-project icon in nav[aria-label="Select view"]) still works, so the features run but never find the board.

How it works

One rule for every GitHub CSS-module class we match: match the local name followed by __ (e.g. [class*="boardContainer__"]), never the file-module__ prefix. That substring is present in both generations (Board-module__boardContainer__abc and boardContainer__xD7rX8), so the fix does not depend on which build a user gets. Where GitHub gives us a stable attribute, prefer it: columns become [data-board-column] frames.

Standup column scan on a grouped board, as rendered live: each group row has its own [data-board-column] frames holding the cards, and the header row above repeats them without cards inside horizontalGroupHeader__. The scan takes .board-view-column plus [data-board-column] frames outside the group header; a column's name falls back to its data-board-column value (read from GitHub, not guessed) when the frame has no visible heading.
