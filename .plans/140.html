#140 · Quick jump: your work from any GitHub page

cattanisimone/gh-reloaded#140 · Size: normal · Type: feat (minor) · Goal: one shortcut opens a read-only panel listing your assigned issues, review requests, recent items and active repositories, filterable by typing.

What changes for users

  • A Quick jump panel opens with a browser shortcut on any github.com page (outside text fields): Your work, Recent, Active repositories, scoped to This repository, This owner or Everywhere (Tab switches).
  • Typing filters everything already fetched and stored, locally; the last row hands the text to GitHub's search.
  • A new Quick jump row in Settings → Features, with a Shortcut selector (browser shortcut, or ⌘K/Ctrl+K by explicit choice) and Clear recent items.
  • New local data: up to 50 recently opened issues, pull requests and repositories, in this browser only. Nothing is written to GitHub, no new permission.
  • With no GitHub token saved, the feature does not appear.

Order of work: gates first

Stop condition from the issue. Before any feature code, the implementation runs Gate A (native command palette opened empty, on a test account with the preview on: repository page, dashboard, /notifications) and Gate B (GitHub changelog since 2025-07-16: navigation, search, palette, jump, dashboards). If either shows GitHub already lists assigned issues or review requests on open, or a personal keyboard jump list ships, the implementation stops and reports back on the PR. Nothing else is built.

Planning-time evidence (not a substitute for the gates): on 2026-11-20 the signed-in header search is now GitHub's quick search dialog (button aria-label="Open quick search dialog, type / to search"). Opened empty on a repository page it lists only repo:…, owner:… and "Chat with Copilot". Ctrl+K on the page body opened nothing on a test account without the palette preview.

Navigation A → B → A, back/forward and reload each count as a visit of the page shown. An open panel closes on navigation, so its scope never belongs to a page that is gone.

How it works

  • Two-phase open. The panel asks the background for cached lists (renders at once, with Recent), then for a refresh. One open sends at most the three GETs for the scope's token; Tab to a scope served by another token record sends at most three more. A list waits at least 60s and at least retry-after/x-ratelimit-reset; while the panel stays open the affected lists are asked once more when the wait ends.
  • Token rule. This repository / This owner use resolveTokenRecord(owner) (mapped, else default); Everywhere uses the default only. No retry with another token, no anonymous request.
  • Classification (pure, in model.js): 401/404/422/non-limit 403 → "cannot read"; rateInfo() limited → "limited"; 5xx/network → "error". Truncation: Link rel="next" (issues, repos), total_count > items (search).
  • Recorder anchors (live, 2026-11-20): repository pages carry meta[name="octolytics-dimension-repository_nwo"] (also after in-page navigation; absent on 404, profile, /notifications, /search) and a header link to /o/r; titles read <title> · Issue #n · o/r and <title> by <login> · Pull Request #n · o/r. A visit is recorded when the URL and title agree (debounced title observer + popstate/turbo:load/pageshow), so redirects and in-page navigation record the final page. No CSS-module class is used anywhere.

Assumptions

  1. A1 Default shortcut: Alt+Shift+K on Windows/Linux; on Mac the issue's Check 4 fallback MacCtrl+Shift+K (⌃⇧K) — rejected: ⌥⇧K, because on the US Mac layout ⌥⇧K types a character and a registered Chrome command consumes the keystroke, which is Check 4's loss condition. Labels come from chrome.commands.getAll(), so a Check 4 result changes one manifest line.
  2. A2 Command keystroke: Chrome consumes a registered command's keys before the page sees them; the extension cannot hand them back. So "the keystroke reaches the page" holds fully for ⌘K/Ctrl+K (no listener without a token or with the browser value); for the browser shortcut it means the extension does nothing. Recorded in the PR and README.
  3. A3 Panel geometry: CSS copies the native quick search box (from 1012px left 91px / right 340px; below, full width) — rejected: measuring GitHub's button on each open, because the panel is a fixed overlay with no container that can break, and fixed numbers are simpler to test; the live check catches a header redesign.
  4. A4 Narrow rules apply below 544px viewport width (Primer's small breakpoint), covering 390 and 320.
  5. A5 Recent rows show o/r #n · Visited <time> without state — rejected: the mockup's Open/Merged, because state is not among the fields the issue allows storing.
  6. A6 Titles and visits come from document.title's fixed format and are recorded only when it names the URL's item — rejected: h1 classes (CSS-module churn).
  7. A7 Owner pages: /<login> (not a reserved GitHub path, not "Page not found"), /orgs/<login>/…, user Projects pages (users/<login>/projects/…).
  8. A8 Filter: whitespace-separated words, all must match, case-insensitive, in title, owner/repo or number (61 or #61).
  9. A9 Search hand-off puts the qualifier first (repo:o/r text), as GitHub's own quick search does.
  10. A10 Placement: "Clear recent items" ends the description (mockup), "Change shortcut" sits beside the selector.
  11. A11 Cache in chrome.storage.session — rejected: the shared 60s in-memory map, because cached rows must outlive a minute for the limited state and survive a service-worker restart, while never touching disk.
  12. A12 Scope keys: Shift+Tab also switches (two values); focus stays in the input; scope buttons are clickable; clicking the backdrop closes.
  13. A13 Token requirements list: Quick jump is not added to Settings' "required permissions" table until Check 3 shows what the reads need; the missing-permission experience stays as today.

Risks and open questions

  • A gate stops the work. Default: stop, report on the PR, build nothing.
  • GitHub's palette still fires with ⌘K chosen (its listener runs before ours). Default: per Check 7, ship without the ⌘K value and say so in the PR.
  • Header redesign moves the native quick search box. Default: the panel still opens (fixed overlay); the layout spec documents the numbers and the live check is repeated.
  • Search API deprecations (/search/issues). Default: the list follows the degraded state ("cannot read" or "error") and the fixed row still opens GitHub's page.
  • Scope of the PR is large (~a dozen files). Default: commits per slice (model → background → recorder → panel → settings → docs), pushed as each group goes green.

Out of scope

  • Commands that change issues or pull requests, AI, own indexing, code or Projects search, our own remote search beyond the hand-off row, favourites, syncing history, taking ⌘K by default, any new permission or token type.
