#59 · Full-width board: titles, cards, lanes and edges on a narrow window

Size: normal (layout across two features, new fixture) · Goal: the stretched board stays legible and lines up with the filter bar at 1500, 1100 and 800px, with and without swimlanes.

What changes for users

  • Column titles stay on one line, end in “…” when they do not fit, and show the full title in a tooltip. The count badge and the “…” menu keep their size.
  • Columns get a 200px minimum (was 140px). Below that the board scrolls sideways, which is what GitHub does by default.
  • Card content (labels, title, avatar) stays inside the card's border: long labels end in “…” instead of spilling out.
  • With swimlanes, each lane header spans the full scrollable width and scrolls with its columns. The whole board keeps one horizontal scrollbar.
  • The board's left and right edges line up with the filter bar and the view tabs, with or without a vertical scrollbar.

How it works

What the live board looks like (probed anonymously on orgs/github/projects/4247?groupedBy[columnId]=Labels)

Moving parts

Anchors (no CSS-module prefix): [class*="boardView__"], [class*="horizontalGroupHeader__"], [class*="horizontalGroupAreaContainer__"], [class*="styledGroupHeaderWrapper__"], columns by [data-board-column] (attribute, not class), titles by the column's h2 heading, cards by .board-view-column-card and ul[aria-label="Fields"], the gutter by nav[aria-label="Select view"]. The old Board-module__… forms stay listed next to the current ones, as today. If the view tabs are missing, the gutter variable is not set and GitHub's own 16px padding applies: no other container is used as a fallback.

Live check (done for this plan): GitHub's public roadmap board opens anonymously, including with swimlanes (?groupedBy[columnId]=Labels). With the extension at 800px: columns start at x24 (filter bar and tabs at x16); with columns forced to their minimum, the lane header ends at x768 while the columns reach x1008; label tokens spill past a 162px card; titles wrap when columns shrink. A prototype of the CSS above, injected on the same page, gave columns, lane headers and the filter bar a common x16 edge, lane headers ending with the last column, single-line titles and one horizontal scroller. Not reproducible anonymously: “…” column menus (members only, 0px wide here) and a 7-column board with the issue's exact titles. The fixture covers both.

Risks and open questions

  • Minimum column width (default: 200px, which fits ~12 characters of title next to the count and menu). 180px keeps more columns visible but truncates sooner.
  • Headless Chromium uses overlay scrollbars, so the scrollbar case is only tested with a forced classic scrollbar in the fixture. Default: measure offsetWidth − clientWidth at runtime, not a constant.
  • width: max-content on the lane area could fight GitHub's virtualised lane rendering. Default: keep min-width:100% so a narrow board still fills the width, and check the live page again in IMPLEMENT.
  • Setting title on React-owned headings. Default: only when GitHub set no title, and re-applied on each scan in case a re-render drops it.

Out of scope

  • Re-showing the hidden “+” add-column button.
  • Table and Roadmap views.
  • Standup's “Standup” button overlapping the view tabs at 800px (seen during the probe): listed under Follow-ups.
