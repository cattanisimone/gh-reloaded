#59 · Full-width board: titles, cards, lanes and edges on a narrow window

Size: normal (layout across two features, new fixture) · Goal: the stretched board stays legible and lines up with the filter bar at 1500, 1100 and 800px, with and without swimlanes.

What changes for users

  • Column titles stay on one line, end in “…” when they do not fit, and show the full title in a tooltip. The “…” menu never shrinks. When the title would get fewer than about 6 characters, the count badge gives way first: it is hidden and the count moves into the tooltip (“Waiting Review · 12”).
  • The minimum column width goes from 140px to 150px, so columns still shrink before the board scrolls sideways, as the README promises. At 1100px a 6-column board still fits with no sideways scroll.
  • Card content stays inside the card's border at the minimum width: labels end in “…”, the title wraps between words, and the avatar is never clipped.
  • With swimlanes, the lane headers end where the columns end and scroll with them, using GitHub's own single board scroller. A fallback covers boards that scroll lane by lane (see below).
  • The board's left and right edges line up with the filter bar and the view tabs, also when the vertical scrollbar appears or disappears after load.

Column widths and titles · 6 columns, 8px gap

Measured on the live header: the parts around the title take about 125px (17px left inset, 16px colour dot + 8px gap, 8px gap + count badge 22–31px, 8px gap + 28px “…” menu for members, 9px right inset). Average glyph width about 9px. So the title gets w − 125 px with the badge and w − 86 px without it. The badge is hidden when the title would get less than 54px (6 characters), that is below about 179px. The script measures this on each column (a 3-digit count hides sooner) instead of using a constant.

Moving parts

One scroller, and the fallback

Probed anonymously on the public board (grouped by Labels and by Assignees, 1100px): the only horizontal scroller is boardView__ (scrollWidth 1464, clientWidth 1100). Lane headers are position: sticky and already span the content width (1424px) on GitHub's own layout; the column-header row is sticky at top: 0. The lane headers break only because the extension zeroes the lane area's inline min-width. So the plan adds no scroller and moves nothing: it only sizes the lane area and the header row to max-content (with min-width: 100%), and it never touches overflow, position, drop zones or data-dnd-* elements.

Fallback: each lane scrolls on its own (the issue saw a scrollbar per lane; not reproduced anonymously, maybe on large or virtualised boards)on each scan, a lane container with overflow-x: auto|scroll and scrollWidth > clientWidth → body.ghfw-lane-scrollKeep GitHub's per-lane scrollers. Size each lane header to its lane's scroll width, and make the header's label sticky at the lane's left edge (position: sticky; left: 0 on the inner content), so the name stays visible and the header ends where that lane's columns end. No scroll syncing between lanes.

If drag and drop or the sticky row break in the primary mode during the live check in IMPLEMENT, the fallback CSS becomes the only mode, and the PR says so.

Edges that stay aligned after load

The scrollbar width (offsetWidth − clientWidth of boardView__) is measured on the 800ms scan, on resize, and by a ResizeObserver on boardView__ and its first child. That catches a scrollbar that appears or disappears when a lane collapses or a filter changes, with no window resize. The right padding is max(0, gutter − scrollbar), so the last column ends 16px from the window edge in both cases.

Cards at 150px (card ≈ 132px wide)

  • Labels: max-width: 100%, one line, “…”; the label list wraps to more lines but never overflows.
  • Title: wraps between words; a single word longer than the card breaks (overflow-wrap: anywhere) instead of overflowing.
  • Avatar and the issue number row: flex: none on the avatar, min-width: 0 on the text next to it, so the avatar is never clipped and the right border stays visible.

Anchors (no CSS-module prefix): [class*="boardView__"], [class*="horizontalGroupHeader__"], [class*="horizontalGroupAreaContainer__"], [class*="styledGroupHeaderWrapper__"], columns by [data-board-column] (attribute, not class), titles by the column's h2 heading, cards by .board-view-column-card and ul[aria-label="Fields"], the gutter by nav[aria-label="Select view"]. The old Board-module__… forms stay listed next to the current ones, as today. If the view tabs are missing, the gutter variable is not set and GitHub's own 16px padding applies: no other container is used as a fallback.

Live check (done for this plan): GitHub's public roadmap board opens anonymously, including with swimlanes (?groupedBy[columnId]=Labels). With the extension at 800px: columns start at x24 (filter bar and tabs at x16); with columns forced to their minimum, the lane header ends at x768 while the columns reach x1008; label tokens spill past a 162px card; titles wrap when columns shrink. A prototype of the CSS above, injected on the same page, gave columns, lane headers and the filter bar a common x16 edge, lane headers ending with the last column, single-line titles and one horizontal scroller. Not reproducible anonymously: “…” column menus (members only, 0px wide here) and a 6-column board with the issue's exact titles. The fixture covers both.

Grouped by assignee: ?groupedBy[columnId]=Assignees opens anonymously, but this board has one lane, “No Assignees”, with no avatar and no Effort pill. The final probe runs there too, and the PR will say Not verified on live github.com for lane headers with an avatar, a name, a count and an “Effort” pill, and for GitHub's own drag and drop. The maintainer should look at: a board grouped by assignee at 800px (lane header ends with the last column, avatar and pill not clipped) and dragging a card into a column that is scrolled into view. The fixture's lane headers carry an avatar, a name, a count and an Effort pill, built from the measured structure (groupHeaderContainer__ › IconButton + groupHeaderContent__ › SanitizedHtml__ + AggregateLabels__).

Risks and open questions

  • Minimum column width (default: 150px: 7 characters of title with the badge hidden, 4.9 columns at 800px). 160px gives 8 characters but only 4.6 columns at 800px.
  • At 1100px the badge is hidden on members' boards (2-digit counts). Option: show the “…” menu only on hover or focus to win 36px and keep the badge. Default: no, keep GitHub's always-visible menu.
  • Headless Chromium uses overlay scrollbars, so the scrollbar case is only tested with a forced classic scrollbar in the fixture. Default: measure offsetWidth − clientWidth at runtime, not a constant.
  • width: max-content on the lane area could fight GitHub's virtualised lane rendering. Default: keep min-width: 100%, and switch to the per-lane fallback for good if the live check shows a break.
  • Setting title and a class on React-owned headings. Default: only when GitHub set no title, re-applied on each scan in case a re-render drops it.

Out of scope

  • Re-showing the hidden “+” add-column button.
  • Table and Roadmap views.
  • Standup's “Standup” button overlapping the view tabs at 800px (seen during the probe): listed under Follow-ups.
