#142 · Viewed count per folder in the Files changed file tree

cattanisimone/gh-reloaded#142 · Size: normal (new UI surface, new background read) · Goal: every folder row of the new Files changed tree says, read-only, how many of the changed files below it the signed-in user marked “Viewed”.

What changes for users

  • Each folder row in the file tree gets a small indicator at its right edge: ✓ all viewed, a partial ring + 3/7, an empty ring + 0/3. A parent counts every file below it at any depth.
  • Ticking GitHub’s own “Viewed” button updates every containing folder at once; collapsing, expanding and filtering change nothing.
  • With a token already configured, one read-only GraphQL read makes counts exact on large pull requests; without one, the rendered “Viewed” buttons are used and folders that cannot be proven show a dashed ring (2+/108) instead of a guess.
  • Nothing is written to GitHub, no native control is clicked, no token permission is added. A new Viewed per folder switch in Settings → Features (on by default).

How it works

  • Live markup (probed 2026-11-24, signed in, read-only): ul[role=tree][aria-label="File Tree"]; folder li[role=treeitem][aria-expanded] with id = full path (compacted chains such as features/quick-jump are one row) and aria-labelledby → content element; file li with id = path, aria-label = file name and a[href^="#diff-"]. Collapsing a folder unmounts its descendants (161 of 331 items left after collapsing compiler), so paths are remembered from the first full view. Diffs: div[role=region][id^="diff-"] with button[aria-pressed][aria-label="Not Viewed"]; 41 of 210 rendered at load, 70 after scrolling. Counter text “0 of 210 files viewed”. Anonymous visitors get the classic page.
  • Path of a button: its region id → the tree link with the same #diff-… href (exact, rename-safe); second choice the region heading text with bidi marks stripped.
  • File list: the API list when the read succeeded; otherwise the remembered tree list, proven complete only when its size equals the counter’s M. Not proven → every folder is Unknown part (no folder can be shown exact, AC 11/12).
  • Query: repository(owner,name){pullRequest(number){files(first:100,after){totalCount pageInfo{hasNextPage endCursor} nodes{path viewerViewedState}}}}, up to 30 pages (GitHub’s 3000-file limit). VIEWED = viewed; UNVIEWED, DISMISSED = not viewed. Checked on 2026-11-24 with a read token on a public pull request: the query is accepted and returns UNVIEWED per file.

Data, permissions, privacy

  • Token permissions: none. The read uses the token already mapped to the repository owner (or the default one), only if one exists. Any failure is silent and falls back to the page.
  • Sent: one paginated GraphQL query per Files changed visit (owner, repository, number). No mutation, no other request.
  • Stored: only ghvfEnabled. Paths and viewed states live in the tab’s memory and are dropped on leaving the pull request.

Risks and open questions

  • Appending into a React-owned row. React may re-render or remount the row and drop the indicator or the aria-describedby addition. Default: idempotent rescan on mutations restores both; tested by remounting rows in the fixture.
  • Description via aria-describedby on an aria-hidden role=img. Default: verified in the CDP accessibility tree; if Chrome does not expose it, the indicator stays visible to AT inside the row label (count read with the name) and the PR says so.
  • Counter text not found (wording change). Default: the tree list is not proven complete without a token → Unknown part (honest, less useful); with a token the API list decides.
  • Which user tokens can read viewerViewedState (fine-grained vs classic). Default: whatever fails falls back silently; nothing is requested.
  • Very large pull requests (300+ files, tree truncated). Default: API list wins; without it the counter mismatch makes folders Unknown part.

Assumptions (product choices the issue left open)

  1. Count read as the row’s description (id added to aria-describedby, indicator aria-hidden) — rejected: count inside the row name, because AC 6 reads it after “expanded” and the row name should stay GitHub’s.
  2. Tooltip is a Primer-style bubble below the indicator, right-aligned, on hover — rejected: native title, because the mockup shows the bubble and title is delayed and unstyled.
  3. While the read is in flight, every folder not fully known shows Loading — rejected: dashed ring during the read, because it would claim “cannot be read” and then flip.
  4. When the file list itself is not proven (no token, tree size ≠ counter total), every folder is Unknown part with k+/? or ? — rejected: counting the listed files, because a folder could miss files (AC 12).
  5. Commit-range and single-commit views show nothing — rejected: range tree with PR-wide state, because counts would mix two scopes.
  6. Switch “Viewed per folder”, on by default — rejected: opt-in, because the feature is read-only and quiet like Resolved conversations.

Out of scope

  • Marking or unmarking anything (no bulk mark, no click on native checkboxes, no markFileAsViewed).
  • Changes to the native counter, per-file buttons, “Viewed files” filter; indicators on file rows; click-to-filter; keyboard focus on the indicator.
  • The classic Files changed page; new token permissions, Verify access checks, README permission rows.
