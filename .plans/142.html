#142 · Viewed count per folder in the Files changed file tree

cattanisimone/gh-reloaded#142 · Size: normal (new UI surface, new background read) · Maturity: Experimental (switch badge and README heading) · Goal: every folder row of the new Files changed tree says, read-only, how many of the changed files below it the signed-in user marked “Viewed”.

What changes for users

  • Each folder row in the file tree gets a small indicator at its right edge: ✓ all viewed, a partial ring + 3/7, an empty ring + 0/3. A parent counts every file below it at any depth.
  • Ticking GitHub’s own “Viewed” button updates every containing folder at once; collapsing, expanding and filtering change nothing.
  • With a token already configured, one read-only GraphQL read makes counts exact on large pull requests; without one, the rendered “Viewed” buttons are used and folders that cannot be proven show a dashed ring (2+/108) instead of a guess.
  • Nothing is written to GitHub, no native control is clicked, no token permission is added. A new Viewed per folder switch in Settings → Features, marked Experimental like Quick assignment and HTML preview (the API path is not yet verified with users’ tokens), on by default because it only reads.

Tooltip placement

  • Where it lives: one bubble element div.ghvf-tip with popover="manual", appended to document.body (or to the open <dialog> containing the tree, should GitHub ever ship a drawer), shown with showPopover(). It is in the top layer: not clipped by the tree’s scroll container (FileTreeScrollable, overflow: auto), not under the sticky pane or headers. position: fixed, pointer-events: none, aria-hidden="true" (the text is exposed through the row, below).
  • Position, from the indicator’s border box: below it with a 4px gap, right edges aligned; flipped above when its bottom would pass the viewport bottom − 8px; left clamped to [8px, viewport width − 8px − bubble width]; max-width: min(320px, 100vw − 16px), text wraps inside the bubble if longer.
  • When: shown on pointer hover of the indicator; hidden on leave, on scroll of the tree or the page, on Escape, on route change and when the feature is switched off. Not focusable (out of scope per issue); keyboard and screen-reader users get the same text from the row.
  • Narrow widths: below about 1075 px there is no tree and no bubble; the 1080px viewport is the narrowest case tested.

Accessibility and its gate

  • Design: the indicator is aria-hidden="true" with an id; that id is appended to the folder treeitem’s aria-describedby, keeping GitHub’s own id already there (observed live: Primer points it at an empty visually-hidden node). Expected reading: “rustc_abi/src, expanded, level 2, 3 of 4 files viewed”: name unchanged, the text as the description. A MutationObserver on aria-describedby re-adds our id in the same task when React rewrites the attribute.
  • Gate (deterministic, e2e with CDP): Accessibility.getPartialAXTree on the folder treeitem must return description = the exact tooltip text and name = the folder name alone, (a) after the first render, (b) after the fixture re-renders the row the way React does (rewrites aria-describedby to GitHub’s id only, then remounts the row), (c) after a native tick, (d) after collapse and expand. The same check (a, d) runs live in the IMPLEMENT live check on rust-lang/rust#166114.
  • If the gate fails in either place: drop aria-hidden and the aria-describedby addition and use the issue’s own design, role="img" + aria-label = tooltip text on the indicator. The row’s name (computed from its aria-labelledby content) then becomes “rustc_abi/src 3 of 4 files viewed” and the reading becomes “rustc_abi/src 3 of 4 files viewed, expanded, level 2”. The PR states which branch shipped and the gate result.

How it works

  • Live markup (probed 2026-11-24, signed in, read-only): ul[role=tree][aria-label="File Tree"]; folder li[role=treeitem][aria-expanded] with id = full path (compacted chains such as features/quick-jump are one row) and aria-labelledby → content element; file li with id = path, aria-label = file name and a[href^="#diff-"]. Collapsing a folder unmounts its descendants (161 of 331 items left after collapsing compiler), so paths are remembered from the first full view. Diffs: div[role=region][id^="diff-"] with button[aria-pressed][aria-label="Not Viewed"]; 41 of 210 rendered at load, 70 after scrolling. Counter text “0 of 210 files viewed”. Anonymous visitors get the classic page.
  • Path of a button: its region id → the tree link with the same #diff-… href (exact, rename-safe); second choice the region heading text with bidi marks stripped.
  • File list: the API list when the read succeeded; otherwise the remembered tree list, proven complete only when its size equals the counter’s M. Not proven → every folder is Unknown part (no folder can be shown exact, AC 11/12).
  • Query: repository(owner,name){pullRequest(number){files(first:100,after){totalCount pageInfo{hasNextPage endCursor} nodes{path viewerViewedState}}}}, up to 30 pages (GitHub’s 3000-file limit). VIEWED = viewed; UNVIEWED, DISMISSED = not viewed. What was checked (2026-11-24): the factory’s GitHub App installation token (a bot, not a user token) runs this query on the public cattanisimone/gh-reloaded#141 and gets UNVIEWED for each file. That proves the query and field are accepted, nothing about users’ tokens (a bot never marks files). The earlier wording “checked with a read token” meant this; the user-token path is not verified, hence step 1 below and the Experimental mark.

Data, permissions, privacy

  • Token permissions: none. The read uses the token already mapped to the repository owner (or the default one), only if one exists. Any failure is silent and falls back to the page.
  • Sent: one paginated GraphQL query per Files changed visit (owner, repository, number). No mutation, no other request.
  • Stored: only ghvfEnabled. Paths and viewed states live in the tab’s memory and are dropped on leaving the pull request.

Risks and open questions

  • Appending into a React-owned row. React may re-render or remount the row and drop the indicator or the aria-describedby addition. Default: idempotent rescan on mutations restores both; tested by remounting rows in the fixture.
  • Description via aria-describedby to an aria-hidden indicator. Default: the gate in “Accessibility and its gate”; if it fails, the issue’s role="img" + aria-label ships and the row name includes the count.
  • Counter text not found (wording change). Default: the tree list is not proven complete without a token → Unknown part (honest, less useful); with a token the API list decides.
  • Which user tokens can read viewerViewedState (fine-grained vs classic). Default: implementation step 1 records it; whatever fails falls back silently; nothing is requested; the feature is marked Experimental until it is known.
  • Very large pull requests (300+ files, tree truncated). Default: API list wins; without it the counter mismatch makes folders Unknown part.

Assumptions (product choices the issue left open)

  1. Count read as the row’s description (id added to aria-describedby, indicator aria-hidden), subject to the deterministic gate, with the issue’s role="img" + aria-label as the only fallback — rejected: count inside the row name by default, because AC 6 reads it after “expanded” and the row name should stay GitHub’s.
  2. Tooltip is a Primer-style bubble in the top layer (popover, fixed, below and right-aligned, flipped above at the bottom edge, clamped to the viewport), on hover — rejected: native title (delayed, unstyled, not in the mockup) and a bubble inside the row (clipped by the tree’s scroll container).
  3. When a row’s label would fall below 32px, the count is dropped and the glyph stays — rejected: clipping the count, or letting the label reach 0px, because the folder name is the row’s identity and the full text stays in the tooltip and the accessible text.
  4. 0+/108 when some files are known and none of them is viewed — rejected: ?/108, which the issue keeps for “no file known”; it follows the issue’s formula known-viewed+/total.
  5. While the read is in flight, every folder not fully known shows Loading — rejected: dashed ring during the read, because it would claim “cannot be read” and then flip.
  6. When the file list itself is not proven (no token, tree size ≠ counter total), every folder is Unknown part with k+/? or ? — rejected: counting the listed files, because a folder could miss files (AC 12).
  7. Commit-range and single-commit views show nothing — rejected: range tree with PR-wide state, because counts would mix two scopes.
  8. Switch “Viewed per folder”, on by default — rejected: opt-in, because the feature is read-only and quiet like Resolved conversations.

Out of scope

  • Marking or unmarking anything (no bulk mark, no click on native checkboxes, no markFileAsViewed).
  • Changes to the native counter, per-file buttons, “Viewed files” filter; indicators on file rows; click-to-filter; keyboard focus on the indicator.
  • The classic Files changed page; new token permissions, Verify access checks, README permission rows.
