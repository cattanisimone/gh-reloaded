#116 · Make the CI on main green again

Size: simple (test-only, a few lines) · Goal: remove the race in one GitHub Status e2e test without weakening what it proves.

What changes for users

  • Nothing: no extension code changes. The test suite becomes deterministic, so main and every waiting pull request can go green.

Root cause

github-status.spec.js › a tab that becomes visible on a stale snapshot repaints gray before the refresh answers waits for the dot to turn gray, then checks once that the mocked feed has seen 2 requests. The content script repaints gray synchronously and only then sends the refresh message; the request still has to travel content script → service worker → storage.session read → fetch → Playwright router. On a slow runner (CI: 2 shared vCPUs, 626 tests) the gray paint wins and the log still holds 1 entry. Reproduced locally: 1 of 8 runs under 4 parallel workers fails with the same Received length: 1. The test was added in #97; #109 did not touch it, it only made the run longer and busier.

Changes by file

FileChangeWhy
test/e2e/github-status.spec.jsReplace the one-shot expect(log).toHaveLength(2) with expect.poll on the log length; once the refresh request is seen, assert the dot is still gray (the mock holds the answer 4 s). The failure messages say what was missing and how many requests were seen.Same claim (gray comes from the repaint, before the answer), now independent of how fast the request reaches the mock.
