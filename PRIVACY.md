# Privacy Policy

**GH Reloaded** doesn't collect, sell, or share any data. Everything it stores stays in your own browser, and the only network calls it makes are directly from your browser to `api.github.com`, using your own GitHub token(s), and, for the GitHub Status feature, one anonymous request to `www.githubstatus.com` (GitHub's official status page) — never to a server this project runs or controls.

## What's stored, and where

Stored locally via the browser's `chrome.storage.local` (never synced, never sent anywhere on its own):

- **GitHub tokens** — the personal access token(s) you paste into Settings: one default token, plus an optional token per repository owner (an organization or personal account) that needs its own credential. Each request uses the token mapped to the repository it's about, falling back to the default. Once saved, a token is never displayed again, not even in part.
- **Quick-create shortcuts** — the label, URL, icon, color, and project scope of each shortcut you configure.
- **Feature toggles** — which features are turned on or off.
- **Standup mode thresholds** — how many days a card may sit in a review-like column before it is flagged, and the status keywords that count as review-like.
- **UI preferences** — small display choices: the dependency graph's column alignment, how much external context to show, whether transitive dependencies are hidden and the automatic-refresh interval, whether the My Issues dashboard shows the native list or the grouped-by-project view (`ghmiView`), whether its left sidebar is collapsed to an icon rail (`ghmiSidebar`), whether the My Issues feature is switched on (`ghmiEnabled`), and the optional minimum and maximum width of its Project tiles (`ghmiTileMin`, `ghmiTileMax`), whether PR triage on a repository's Pull requests page is switched on (`ghprtEnabled`), whether the experimental Quick assignment on issue pages is switched on (`ghqaEnabled`, off unless you enable it; it sends one read-only request for the issue's assignees to api.github.com to confirm a change and stores nothing from it), whether the linked-PR status on Projects board cards is switched on (`ghlpsEnabled`) and whether you dismissed its missing-token hint (`ghlpsHintDismissed`), and for GitHub Status whether it is switched on (`ghgsEnabled`), whether its incident notice is shown (`ghgsNotice`) and which incident notices you dismissed, as incident ids with the time of the update you dismissed (`ghgsDismissed`; entries for resolved incidents are removed); for the Image gallery whether it is switched on (`ghigEnabled`) and whether it opens automatically (`ghigAutoOpen`), for the Actions log shortcuts whether it is switched on (`ghalsEnabled`) and the last access outcome per repository owner (`ghalsOutcomes`: `ok` or `not-permitted` with its time; no token, repository, URL, job id or log; cleared when you save or remove a token and when the feature is switched off), for the Resolved conversations bar whether it is switched on (`ghrcEnabled`; it makes no request and stores nothing else, the expanded state is never kept), for Split diff: one column whether it is switched on (`ghsocEnabled`; it makes no request, reads only the diff already on the page and stores nothing else, the per-file choice is never kept), and for the notifications engine, which of its modules are switched on (`ghntModules`), whether the native inbox is kept (`ghntNativeInbox`), which triage layout you picked in the inbox's Triage settings panel (`ghntLayout`), how many days a mention counts as recent (`ghntMentionWindowDays`) and which sections of the Grouped sections layout are collapsed (`ghntTriageCollapsed`). Which Project tiles are collapsed is kept in memory only and never stored. The notifications engine reads pull request, issue, comment and review text from GitHub only to match it in memory; none of it is stored.

The public status data the GitHub Status feature reads (overall indicator, affected components, open incidents and their latest update) is kept in `chrome.storage.session`, in memory only, for a few minutes and cleared when the browser closes. It is not personal data and is never synced.

**Test** (Settings → GitHub tokens) sends one row's token, or the token in the edit panel, to `api.github.com`, only when you press it, in at most 7 read-only requests that check what the token can read (8 on the default token, which adds one read of your notifications list for the optional notifications permission); the answer text is shown on that page and not stored. Only a short outcome per permission type (available, denied, unverified or unchecked, the notifications check included) and the time of the test are kept, in `chrome.storage.session`, in memory only: no token, no GitHub answer text and no repository name, cleared when the browser closes or the token is replaced or removed. **Check a specific repository** sends the token to `api.github.com` only when you click **Run checks**, for the repository, issue, project and file you name; the answers are shown on that page and nothing is stored.

None of this leaves your browser except the token itself, which is sent — over HTTPS, directly — only to `api.github.com`, only when a feature you've enabled needs to read issue, sub-issue, dependency, or Projects data, or when you press **Test** or click **Run checks** in Check a specific repository, or, while the notifications engine is on, your notifications list (its first pages on each inbox visit, further pages when you choose a triage category), or, when you press **Test** on your default token, one read-only request to your notifications list (`GET /notifications?per_page=1`) to check the optional notifications permission of a classic token (available from release 1.9.0; nothing is requested when you only open the Triage panel or Settings). GitHub's own [privacy statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement) covers what GitHub does with that request.

## The status request

The GitHub Status feature asks `https://www.githubstatus.com/api/v2/summary.json` for GitHub's public status, from the extension's background service worker, at most once every 5 minutes while a github.com tab is open and visible. When a request fails it retries sooner, after 30, 60, 120 and 240 seconds, and returns to every 5 minutes once it succeeds or the delay reaches that interval. The request has no query string, no cookies or credentials, no referrer and no token, and carries nothing about you, the page you are on or your repositories. It needs no extra permission. Switching the feature off in Settings stops the requests.

## The Actions log shortcuts

On a GitHub Actions job page the extension sends one read-only request per repository and token per minute to `api.github.com` (`GET /repos/OWNER/REPO/actions/jobs/ID/logs`, with the token that applies to the owner) to learn whether that token can read the job's logs, plus one more when you click **Open raw log**. The request does not follow GitHub's redirect and reads no response body, so no log content and no redirect address ever reaches the extension. **Copy gh command** makes no request and its text holds no token. **Open raw log** opens the link GitHub's own page already carries, in a new tab. Only the last outcome per owner (`ok` or `not-permitted`, with its time) is stored, to show a warning in Settings.

## The image gallery

The Image gallery lists the images of the folder you are in from the page's own data or, when that is not available, through the GitHub API (`api.github.com`, with your saved token only when one applies to the repository's owner). The images themselves are loaded by your browser from the same GitHub image URL GitHub's own page uses (`github.com`, which redirects to GitHub's raw content host); no token is sent to those hosts and nothing about the images is stored. If an image cannot be shown, the extension may read that file through the GitHub API to tell why. The one-navigation exception after **Open file on GitHub** is kept in the extension's memory only, for a few seconds, and is never written to storage, cookies or the URL.

## Quick jump

Quick jump opens a personal jump view from any github.com page. It does nothing, and makes no request, unless a GitHub token is saved. While it is on and a token is saved, it keeps **Recent items** in `chrome.storage.local` of this browser profile: for each issue, pull request or repository you open on GitHub, its URL, kind, owner and repository, number, title and the time of the visit (`ghqjRecent`). It keeps at most 50 items for at most 30 days, never syncs them and never sends them anywhere; they are only matched and shown back to you. **Clear recent items** (Settings → Features → Quick jump), switching the feature off and removing the last token each delete them. The feature is experimental and off unless you switch it on; its on/off switch (`ghqjEnabled`) and your shortcut choice (`ghqjShortcut`, the browser shortcut or ⌘K / Ctrl+K) are kept with the other preferences.

When you open the panel it makes at most three read-only requests to `api.github.com` with the saved token that applies (the one mapped to the page's owner, else the default token; **Everywhere** uses the default token only): the issues assigned to you, the open pull requests that ask for your review, and the repositories you pushed to recently (`GET /issues`, `GET /search/issues`, `GET /user/repos`). Their answers are trimmed to the fields shown and cached in `chrome.storage.session`, in memory only and never written to disk, per token and until the browser closes. Nothing is written to GitHub, no other host is contacted and the extension requests no new permission.

## What it reads from GitHub pages

To render its features, the extension reads issue titles, labels, comments, status and when it last changed, sub-issue and dependency relationships, the issues assigned to you (when you open your My Issues dashboard) together with which Projects they belong to and their issue type, and Projects v2 field values, and, for the pull requests listed on a repository's Pull requests page, who is asked to review, each reviewer's latest review verdict, the head commit and the checks result, and, for the issue cards on a Projects board, the pull requests explicitly linked to each issue with their state, review decision and checks result (and the names of failing checks when you open a details dialog) — from the GitHub page you're on and from the GitHub API — and, from your notifications list, the title, repository, reason and read state of each notification (read and unread, never the ones you marked Done), held in memory only for the inbox tab you have open and dropped when you leave or reload it — and displays that information back to you, in your own browser. None of it is transmitted anywhere else, logged, or retained beyond what's listed above.

## What it doesn't do

- No analytics, telemetry, or usage tracking.
- No advertising, and no data sale or transfer to any third party.
- No remotely-hosted code — everything the extension runs ships in the extension package itself.

## Removing your data

Uninstalling the extension removes everything it stored. To clear it without uninstalling, remove your GitHub tokens from Settings, or clear the extension's storage from `chrome://extensions`.
